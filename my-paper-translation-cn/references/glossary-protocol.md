# 子代理翻译术语管理

仅子代理翻译启用。主模型独占维护和发布权限；子代理只读共享表，在自身报告中提交新术语及有依据的修改建议。普通翻译不创建、维护或强制读取术语表，也不要求术语字段。

## 文件与初始版本

文件位于 `tmp_gpt/translation/<论文标识>/`：

- `glossary.json`：当前权威表。
- `glossary-versions/<版本号>.json`：不可变版本快照。
- `glossary-history.jsonl`：版本、指纹和发布理由。
- `glossary-draft.json`：主模型准备的下一版完整草稿，不供代理作为已发布表读取。

主模型根据标题、摘要、关键词和原文定义建立第一版，不必先精读全文。只收录核心概念、专业术语、缩写及易产生译法分歧的表达；依据不足时标记暂定，不凭空确定译法。

草稿格式：

```json
{
  "version": 1,
  "terms": [
    {
      "id": "T0001",
      "source": "policy",
      "aliases": ["policies"],
      "translation": "策略",
      "variants": [],
      "scope": "强化学习中从状态或观测到动作的映射",
      "evidence": ["u0001"],
      "status": "confirmed"
    }
  ]
}
```

`evidence` 引用真实原文单元；示例编号需替换。`aliases` 包含缩写和原词变形，`variants` 为允许的中文变体，`status` 为 `tentative`、`confirmed` 或 `superseded`。同词不同义使用不同编号和 `scope`。已发布编号不得删除或复用；替代时保留旧条目并记录替代编号及理由。

发布命令及版本校验见 [进度协议](state-protocol.md)。发布意外中断时，核对进度登记、快照和当前表，保留产物并恢复一致状态，不直接覆盖版本。

## 版本读取

主模型发布更新后通知运行中的代理。子代理每批开始时检查最新已发布版本，固定使用该版快照并记录完整文件的 SHA-256；批内不切换，更新从下一批采用，不要求全体停工等待。

首次加载核心术语和任务相关条目，后续读取增量及相关条目，不反复加载完整历史。相关性判断包括原词、别名、缩写、定义及适用范围。截取条目仍引用完整版本号和快照指纹。上下文丢失或任务恢复后，从持久化文件重新获取必要规则。

## 报告与裁决

每批报告增加：

```json
{
  "glossary_version": 1,
  "glossary_sha256": "完整版本快照的 SHA-256",
  "term_usage": [{"term_id": "T0001", "units": ["u0001"]}],
  "term_proposals": [
    {"source": "new concept", "translation": "本批实际采用的暂定译法", "scope": "原文含义", "units": ["u0002"]}
  ]
}
```

无使用或建议时对应列表为空。`term_usage` 记录实际使用的已收录术语及位置；`term_proposals` 记录新术语的实际译法、含义和原文位置，可附缩写、备选译法及理由。对已有条目的异议附目标编号及原文依据。记录须来自实际翻译和核对。

已有术语遵循标准译法；新术语先暂定并继续翻译，不等待裁决。无法确定且影响准确性的问题写入 `issues`。

主模型去重并对照原文裁决：采纳则发布新版，已有同义条目则复用编号。处理本批所有建议和冲突后，按进度协议将逐项裁决及理由记入验收历史；发布历史记录实际条目变更，不为单纯拒绝建议生成空更新。后续回查已有裁决，无新证据不重启争论。已确认译法仅在原文定义、适用含义或明确错误支持时修改，不因风格偏好反复切换。

## 变更影响与定点修复

无关新增或仅补充确认状态、证据，不作废旧批次。涉及已用术语译法、适用范围、别名或允许变体的变更，需要核对相关批次；译文本来兼容则重新验收，有冲突则交代理定点修复。状态标记和操作命令见进度协议。

自动关联依赖真实使用记录；遗漏的术语、别名及不同词义仍须结合原文与译文判断，合理的语法变化不能仅凭字符串差异判错。最终按使用记录和检索线索逐项核对，不盲目替换或无差别重译。
